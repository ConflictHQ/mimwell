# Edition boundaries

The candidate ships the portal renderers (including the Easy view, the purpose
home and the opt-in sensemaking workbench), the brain app platform, ontology
profiles/schemas, artifact generators and their Python dependencies. `make build` produces empty
search, plan and graph projections from the selected source tree. `make test`
checks those projections, registry use and portal asset wiring.

The public build uses edition packaging configuration around unchanged engine
modules. It deliberately omits the private component catalogs: private recipes,
discovery/interface metadata and their proof digests are not copied or relabeled
as public verification. User-selected host inputs and optional library drivers
remain outside this empty portal's smoke-test claim.

No private instructions, skills, operating practices, proof receipts, company
knowledge, trackers or Git objects are included. The source SHA and per-file
hashes in `edition.json` are provenance, not publication approval. Secret scanning
and updater ownership are separate checks and cannot approve a file for publication.

The optional native classifier's Cargo dependency revisions stay pinned in
`Cargo.lock`. Model artifacts are absent. The compiled intake host depends on a
compatible local CPython installation; this candidate does not qualify native
redistribution or all consumer platforms.

Publication remains an owner action after reviewing the actual archive, license
and repository destination. A local bootstrap has a new root commit and no remote;
it never pushes, imports the master's history, copies releases/issues or changes
the master's visibility.

The engine's primitive design documents are not shipped. The README summarizes how
to enable sensemaking and scaffold a brain app; the brain app host needs its own
authenticated deployment and is not part of the empty portal smoke test.
