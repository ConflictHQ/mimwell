# Protected snapshot capture

The selected maintenance source includes a capture operation for an adopted retained-content brain when a trusted host supplies a snapshot protection adapter bound to the exact registration. The ordinary command-line interface has no adapter and refuses adopted capture. Selecting this source does not by itself qualify a host or deployment.

## Supported boundary

The selected source supports the declared per-record protection profile when opaque metadata is disabled and offline retain is authorized. It bounds the repository, Git objects, declared authorities and destination route; reserves logical capacity; seals the complete bounded archive before staging; and rechecks the route and provider policy before durable writes and publication.

The serialized payload is bounded to 64 MiB in at most eight 8 MiB chunks. The conservative ciphertext reservation can reach about 87.4 MiB. Insufficient headroom, unsupported profile or metadata policy, or an unavailable route or key refuses before staging. Opening the read-only SQLite authority may create or update coordination sidecars; this is not a zero-filesystem-effects guarantee.

## Not included

This is capture only. It does not provide protected restore, a restore writer, activation, cutover, power-loss recovery, or complete storage-admission coverage. Aggregate capacity remains unavailable. A captured target is not a second active writer. Use separate owner-reviewed restore and authority-fencing procedures.

Source selection and these boundaries do not claim integrated runtime or host qualification.
